# 有奖问卷与安全平台邮件详情

## 1. 问卷与礼品场景

`scenario_type: survey_reward_invitation`。覆盖健康福利问卷、售后满意度调查、会员回馈和问卷后抽奖。消费者参与品牌或服务反馈通常用 `shopping`，员工或校园内部调查可按实际关系用 `workplace`。活动所属地区和语言分别判断。英文邮件可从有依据的英文通知或风险材料取材。显示语言、邮件地址域名或收件方所在地单独不足以确定跨境业务。

- **独立活动邮件。** 允许 `history: []` 并省略 `business_context`。按实际文种写出主办方或发件人的身份声称、联系缘由、参与动作和奖励条件。适合短 HTML 通知时，用醒目的标题、简短正文、图片替代文本（来源已有时）、明确按钮和服务署名。图文短邮件也要让收件人理解要做什么。纯文本版本同样保留必要含义。
- **区分活动阶段。** 受邀填写、完成后获得参与奖、完成后获得抽奖资格、结果公布、奖品发放分别取材。只保留当前阶段能看到的要求。研究后续问卷或领取页时，另约定可用输入和来源，保留它与邮件的关系。
- **核对标签依据。** 正常对照可用来源已经确认的受众、主办方、奖励规则和问卷入口，第三方填写平台、图片、截止期和奖励都可出现。威胁样本须有实际检索的诱因与欺骗机制，并由当前可见的请求或冲突支持标注。若初始邮件仅有礼品主题和问卷按钮，页面或活动归属无法核实，进入 [复核队列](classification-quality.md#5-复核队列的交付约定)。域名拼写或归属提示仅作辅助，云存储服务本身也不能决定标签。

## 2. 从平台详情提取原信

接收 Vigilyx 等平台的截图、复制文本或结构化导出时，先确定要复核原邮件、检查过程还是平台判定。跨层信息按下表处理，不从描述恢复未提供的 MIME。

| 可见内容 | 处理 |
|---|---|
| 原信的主题、发件人和收件人、可见正文、按钮文字、附件名称和类型 | 只提取归属明确的项；邮箱改为 `[EMAIL_n]`。显示时间来自平台时保留为平台时间，确认原信 `Date` 或可用时区依据后才填 `sent_at`。 |
| 按钮目标、外链图片、像素或其他远程资源 | 依据原始 HTML 的 `href`、`src` 或可信结构化导出识别实际值与资源用途，已确认的邮件链接按现有规则保留。复制文本把“显示文本”等界面标签粘进地址时，原样记脱敏转录于处理说明，并注明目标待核。不能截断、补造或从数量推知其他链接。缺失图片仅记录未解析，避免猜图、猜落地页或补入页面索密。 |
| 导航、SVG 字样、操作按钮、预览外壳、状态及威胁判定 | 留在脱敏后的来源或处理说明；“正常”“safe”“待定”、综合风险和模块分数不作为原信内容或训练标签。 |
| SMTP 完成、明文传输、捕获端口和地址、包数、头部计数、缺少 Received、检查不完整和 URL 观察信号 | 作为捕获与检查记录保存。SMTP 完成只描述所观测的会话状态。平台显示缺 Received 不证明完整原件也缺失。检查不完整时明确缺少的范围，结合已看见的内容评估。平台和采集基础设施标识按交付所需最小化。 |

走查参考：`Wellness Gift – Just for You` 和 `START SURVEY` 可作为片段保留。若只有界面转录、一个混入“显示文本”的地址、其余链接和完整正文缺失，应以 `needs_review` 留存，写明需取得原信或结构化链接清单及实际可见内容。可概括它为礼品问卷邀请，暂不确认主办方、网页行为或恶意标签。案例信息留在脱敏的复核材料中。

## 3. 生成及导出

1. **训练语料。** 依据已读过的真实活动、真实业务资料或公开攻击机制，先构筑当前阶段的邮件，再按 `source-adapted` 记录来源和改编。训练记录沿用已有 v2 JSON。HTML 邮件在 `body` 保留阅读所需的文本、层次和已知按钮与目标的对应关系。待核项按原有复核队列交付。
2. **可选的 EML 测试件。** 用户要求 `.eml` 或 MIME 解析测试时，优先从提供的原始 EML 脱敏导出。语料记录用 `scripts/render_records.py --format eml` 导出：标准库生成的 `text/plain` 与 `text/html` 替代内容、回复引用和 `In-Reply-To`；标签只写在 `manifest.json`；附件为占位内容；`X-Corpus-Rendered` 头标明这是渲染件。地址是虚构但看似真实的，可能与真实邮箱重合，只能注入隔离的测试邮件系统；不伪造 `Received`、身份认证结果或 SMTP 会话。仅有平台快照时，从可用事实编写新件并记录其改编身份。未知目标用可见按钮文字呈现，无需制造可点地址。见 [真人感渲染](persona-rendering.md)。
3. **测试与取证边界。** 来源、标签与平台观察单独记录。以邮件解析器回读测试件，核对正文、MIME 部分和已确认的链接。生成文件和检查 HTML 时保持静态离线，不加载外链资源、执行代码、提交问卷或发送邮件。EML 可解析只说明封装符合测试目的，标签仍由可见证据决定。

# 账户安全确认与系统通知

在生成账号核验、邮箱服务、身份验证、隔离摘要及相关仿冒通知时阅读。系统通知属于独立邮件文种，可以简短、使用按钮或表格；其完整性按通知目的判断。[分类与复核要求](classification-quality.md) 适用于正常和威胁两类。

## 1. 覆盖范围

下列 `scenario_type` 为中性业务类别，不编码标签。工作邮箱、办公系统和单位统一身份使用 `workplace`；明确涉及购物或金融账号时沿用对应领域。用途未知的原始片段可进入复核队列，不为凑齐字段杜撰所属产品。产品未知本身不构成恶意证据。

| 主题与分类 | 正常机制与应保留的背景 | 威胁机制与判定边界 |
|---|---|---|
| 账户安全确认 `account_security_verification` | 账号、触发事项、待确认操作及适用渠道；可有确认按钮和处理期限 | 冒称安全核验，引导提交凭证或授予不相符的权限。仅称“需要确认”“影响使用”不足以定类 |
| 新设备／异常登录 `unusual_signin_alert` | 服务报告登录事件，供用户确认是否本人；时间、设备、地点按资料可用性填写 | 借异常登录声称锁定账号并索密；警报报告危险事件不表示警报邮件本身恶意 |
| 密码重置／找回 `password_reset_notice` | 区分本人发起、系统收到重置申请、重置完成与操作撤销提醒 | 诱导向联系人交出密码或验证秘密；意外收到真实重置通知也可能是他人尝试触发，不直接把通知定为钓鱼 |
| 密码到期／策略更新 `password_policy_notice` | 核实所用系统确有相关策略及适用人群、期限 | 仿冒到期提醒引流索密。不得给所有产品套同一密码轮换政策或固定三天期限 |
| MFA／通行密钥设置 `authentication_method_setup` | 核实单位安排与本人正在进行的设置，保留授权对象及方法 | 借注册或安全升级诱导批准他人会话、注册非本人设备或交出恢复秘密；验证码出现或认证页面属于官方域名都不能单独证明正常 |
| 邮箱容量／存储配额 `mailbox_storage_notice` | 核实配额、已用状态、影响和适用的清理／扩容途径 | 借容量超限要求交出凭证或无依据付费；正常付费扩容和容量告警按产品实际规则判断 |
| 账号停用／休眠到期 `account_lifecycle_notice` | 实际账号状态、资格、适用期限和保留／停用流程 | 冒称立即删除以诱导不相干操作；紧迫措辞只是背景，不能充当充分证据 |
| 邮箱迁移／服务升级 `mail_service_migration` | 已公布的迁移安排、受影响账号、操作范围与服务时间 | 借迁移索取原密码、无关数据或要求运行来源不明的程序；不能仅凭“升级”定性 |
| 隔离摘要／邮件释放 `message_quarantine_review` | 正常网关摘要列出邮件和允许的审核、释放或申请释放动作 | 仿冒隔离摘要引流索密；区分“系统通知是否可信”与“摘要列出的邮件是什么标签” |
| 退信／投递失败 `mail_delivery_status` | 关联实际发送邮件，区分延迟、拒收、附件或容量限制 | 借恢复投递要求交出密码或执行无关操作；退信、转发和引用原信内容本身不证明恶意 |
| 共享文档／会议访问 `shared_resource_access` | 已知协作对象、资源、访问请求与合理认证范围 | 借文档或会议诱导授予不相称的访问权限，或授权并非本人发起的会话；不能把正常登录入口直接当作授权合法性的证明 |

表中条目用于安排检索和覆盖，不代表所有产品都有上述邮件通知。使用具体服务时重新核实渠道、产品版本、地区、租户策略和适用日期；缺少该邮件流程的原始依据时，可独立改编单位通知并说明来源只支持相应功能。

## 2. 系统通知的自然写法

- 选择其真实形态：短纯文本、HTML 渲染后的卡片、单列表格、按钮提示、隔离摘要或自动回复。正文可以只有通知对象、触发或声称事由、当前动作／状态和系统署名。无需添加人工自我介绍、长篇交易前情、“顺颂商祺”或虚构联系人。
- 按关系使用“尊敬的用户”“您好”、账号称呼或直接的系统标题。已提供的个人用户名用 `[USER_1]` 等一致脱敏，不能为了显得真实生成真实个人标识。
- 可保留“立即查阅”“检查活动”“确认账户”等按钮文字、服务署名、版权年份和“此邮件由系统自动发送，请勿回复”。这些元素可同时用于两类样本；不能把它们当作真伪证明。
- 新编正文保留自然的标题、正文、操作和页脚层次，适合时用短段落或表格，不强行铺成长信。通常可用 `concise`；只有实质内容达到既有详细契约时才用 `detailed`。
- 根据用途展开必要信息，例如已知的触发事件、被影响的服务或操作的含义。没有资料时不补具体登录地点、设备、账户状态或政策；发件人的声称与客观已知状态分开记录。
- 原文转换中的空表格、重复分隔符和布局单元可规范化，但要保留阅读次序、按钮文字、必要列表和关联关系。正常与恶意采用相同清洗规则，并在 provenance 记录实际转换；不把排版残留当成恶意线索。
- 已取得的 URL 保留原值及按钮文字与目标的对应关系，不再统一替换为 `[URL_n]`。按原件保留域名、路径、查询串等可见信息；个人标识例外按 [数据边界](realism-details.md) 最小化处理。保留链接不等于访问它，也不代表知道其页面内容。按钮缺失目标时保留文字，并在输入之外记录缺失项；不能杜撰网址、把来源报告网址充当按钮目标，或在按钮边写“恶意链接”泄露答案。

正常核验流程中的“用户在自己发起的会话中输入验证码”和“把验证码交给他人”有区别；同时还须核对授权对象。合法认证服务也可能被用于批准他人的会话，因此需要足够的当前可见证据。缺少这部分观察时保留待核实，不把后续流程移到正文中补结论。

## 3. 用户提供的安全确认片段如何处理

该片段包含“账户安全确认通知”“3 天内完成”“立即查阅”、自动发送说明与 `System SEV Service`／`Security Verification Service` 等署名文字。它用于检验覆盖和处理规则，不在维护 Skill 时生成新训练记录。

1. 分开疑似网关／客户端添加的管理员警告、“检测结果：垃圾邮件”和发件人通知正文；确认层次后将外部裁定留在输入之外。无法确认来源层次时记录待核实，不据提示执行链接操作。
2. 保留通知、期限、按钮和服务页脚的自然结构；清理空表格，不因正文短就补成业务故事。账号称呼脱敏，版权年份仅表示原文写法，不证明发送时间或主体合法性。
3. 把泛化服务署名视为发件人使用的显示文字。它没有自动成为已核实机构的资格，不能擅自映射为 Microsoft、单位 IT 部门或已验证服务；也不能因为陌生就断言恶意。
4. 当前片段没有实际发件地址、按钮目标及账号操作背景。在默认语义识别范围内，这些文字不足以给出有充分依据的正常或恶意结论，应走复核队列。“垃圾邮件”裁定不替代原邮件恶意内容的证据。
5. 用这一片段走查 Skill 时，验收点是识别系统通知文种、隔离外部裁定、保留信息不足及避免强行扩写。若未来取得实际按钮 URL，原值纳入约定输入并重新复核；不推定它当前仍提供历史恶意服务，不把后续页面行为回填到原邮件。其他额外证据同样不得编造。

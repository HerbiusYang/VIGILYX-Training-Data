# 真实误报回灌与良性邮件生成

检测器把正常邮件判为恶意（误报），或放过了恶意邮件（漏报）后，用本页把真实样本纳入语料，并围绕误报主动生成良性邮件。良性邮件是独立的生成任务，不只是恶意样本的配对对照。

## 1. 登记真实误报和漏报

1. **先核实结论。** 人工核实后才登记。误报要有支持正常性质的依据，例如已签约的供应商、本人发起的操作、已知的营销平台，写入 `detector_feedback.review_basis`。仍不能确定的进入 [复核队列](classification-quality.md#5-复核队列的交付约定)。
2. **保留原件，按 `redacted-source` 登记。** 来源条目使用 `origin: user_supplied`，不需要网址。所有来源都是用户提供时可以省略 `retrieval`，不得编造检索记录。
3. **脱敏。**
   - 个人姓名、邮箱和个人登录名换成占位符，并在 `render` 中声明。
   - 收件方（用户自己的单位）默认改成 `[ORG_n]` 虚构机构。
   - 外部发件方的实际域名用 `domain: observed` 保留，正文链接保留原值。
   - 改写措辞会变成 `source-adapted`；原件只做脱敏和非实质排版。
4. **剥离外部裁定。** 网关横幅、风险评分和“检测结果”移出 `input`，按 [分离原邮件与外部裁定](classification-quality.md#3-分离原邮件与外部裁定) 处理。检测器当时的判定只记在下面的位置：

```json
"provenance": {
  "kind": "redacted-source",
  "detector_feedback": {
    "detector": "Vigilyx",
    "observed_verdict": "malicious，风险评分 87",
    "observed_at": "2026-11-10",
    "outcome": "false_positive",
    "review_basis": "发件方为已签约的电子发票服务商，链接指向其官方查验页，收件人当天确有开票申请"
  }
}
```

这段只演示字段结构，不是真实案例。规则如下：
- `outcome` 为 `false_positive` 时，`target.label` 必须是 `benign`；为 `false_negative` 时必须是 `malicious`。标签是核实后的结论，不是检测器的判定。
- 为该记录设置 `source_group`，例如 `fp_20261110_01`，后续衍生的样本共用这个值。
- `detector_feedback` 只用于真实原件。

## 2. 找出触发特征

把误报的触发特征写进批次说明或 `scenario`，不进入 `input`，供衍生生成时参考。

| 常见误报触发 | 例子 |
|---|---|
| 账号与认证 | 本人操作后收到的登录提醒、MFA 设置、密码到期通知，带按钮和期限 |
| 链接与跳转 | 营销平台的跟踪链接、短链、第三方问卷、在线文档或网盘、很长的查询串 |
| 发件地址 | 小供应商或个人用免费邮箱；营销邮件经第三方发信平台发出；发件域名与品牌名不一致 |
| 金钱与附件 | 发票、对账单、付款通知、压缩包、带宏的表格 |
| 语气与格式 | 紧急、限时、中奖或福利、英文模板、以图片为主的 HTML |

## 3. 围绕误报生成良性邮件

每条核实过的误报可以衍生若干良性邮件，建议 3–10 条。

- **保留触发特征，变换无关表层。** 换行业、人物、金额、发信平台和文体，按 [画像卡](writing-brief.md#3-画像卡) 抽取写作者，按 [写作简报](writing-brief.md) 交给独立写作者。
- **正常性质要在输入中可见。** 例如本人发起的操作、已知的业务往来、与历史一致的金额和流程。证据码用 `process_consistent`、`expected_next_step`、`matches_prior_reference` 或 `verification_via_known_channel`。不能仅因为“没看到明显恶意”就标为正常。
- **衍生样本按改编登记。**
  - 用 `source-adapted`，把原误报列为 `material` 来源（`origin: user_supplied`）。
  - 按 [来源改编](source-grounding.md) 记录改动。
  - 与原件共用 `source_group`，不加 `detector_feedback`。
- **需要对照时另写恶意样本。** 在同一场景写恶意版本，让模型学到真正的区别。例如同样是发票通知，恶意版把查验链接换成仿冒域名，并要求登录邮箱。

## 4. 日常良性邮件

混合批次和良性批次都要覆盖普通往来：
- 会议安排、材料交接、进度确认、报价、物流和售后。
- 正规营销、订阅通知、自动回复、退信、日历邀请、内部公告。

它们按 [选题规则](topic-selection.md) 与其他场景一起随机抽取，同样需要流程依据、真人写法和 `render` 声明。良性批次中，带链接、附件、期限或从免费邮箱发出的样本要占合理比例，不能只生成没有链接的平淡邮件，否则模型会把“有链接”学成恶意信号。

## 5. 划分与评估

- **整组划分。** 原件和衍生样本按 `source_group` 一起划分到同一集合。
- **单设真实误报回归集。** 回归集只放核实过的原件，不参与训练。每次训练后检查这些邮件是否仍被误报。如果决定把原件也放进训练集，回归集就不能再衡量泛化能力，要在报告中说明。
- **按来源报告误报率。** 分开统计真实原件、误报衍生样本和一般生成样本。
- **漏报同理。** 真实漏报（`false_negative`）也走同样流程。衍生恶意样本时，保持来源支持的机制和观察阶段，不把后续页面里的行为提前写进邮件。
